## DEC-NEW-001 — جایگزینی سند مرجع (2026-11-17، Accepted)

سند «دستور جامع طراحی، توسعه و ساخت نرم‌افزار مازندشت» نسخه ۱.۰ (مالک محصول: مهندس مجید عیسی‌پور) به‌عنوان **سند مرجع حاکم** ثبت شد (`docs/MAZANDASHT_SPEC_FA.md`) و در موارد تعارض بر `PROJECT_SPEC.md` v1.1 مقدم است. `PROJECT_SPEC.md` برای تاریخچه حفظ می‌شود.

پیامدها:
- فناوری: WPF + C# + .NET Framework 4.8 + SQLite x64 (جایگزین Python/Tkinter).
- سیستم‌عامل هدف: Windows 8.1 x64 به بالا (جایگزین Windows 7 SP1).
- مدل کاربری: Single + تأیید مدیر.
- موجودی: Simple + Detailed از یک Stock Movement Ledger.
- پول: ریال صحیح در دیتابیس؛ تومان صرفاً واحد نمایش (Toman = Rial / 10).
- وزن: گرم صحیح؛ حداکثر ۳ رقم اعشار کیلوگرم در قالب‌های فعلی؛ گردکردن ۲ رقم اعشار در موتور اصلی ممنوع.
- دکمه عملیات سریع +، نمایشگر دوم، Import هوشمند Excel/CSV، Reset با عبارت `RESET MAZANDASHT`، Backup با SHA-256 و Manifest.

- DEC-NEW-010 — **جمع‌بندی schema_v002** (2026-11-17، Accepted، اجراشده): به‌جای بازنویسی ۵۲ جدول، v002 ترکیبی از **دو بازسازی جدول** (که SQLite راه دیگری برایشان ندارد) + ستون‌های افزودنی + تریگر + ویو + فرهنگ داده درون‌دیتابیسی است. فایل: `database/migrations/002_v002_workbook_alignment.sql`. نسخه اسکیما ۲.

  **چرا دو بازسازی اجباری بود:** SQLite نه `ALTER ... DROP CONSTRAINT` دارد نه امکان شل‌کردن `NOT NULL`.
  1. `basket_movements` (G-11): CHECK قدیمی `TRANSFER`/`OPENING` را رد می‌کرد، یعنی قالب ۰۷ عملاً قابل واردسازی نبود. واژگان جدید `PURCHASE/ISSUE/RETURN/TRANSFER/OPENING` + `RECEIVE` به‌عنوان نام قدیمی سازگاری.

  **سیاست ارتقای داده‌های قدیمی (مهم):** ردیف قدیمی اگر مقصدش به فاکتور واقعی برسد، به ستون تایپ‌دار **ارتقا** می‌یابد و جفت قدیمی پاک می‌شود (وگرنه یک ردیف دو مقصد می‌شد). اگر مقصد قابل‌حل نباشد، ردیف **دست‌نخورده** می‌ماند و در `schema_field_notes` با وضعیت `LEGACY` دیده می‌شود؛ هرگز حدس زده یا حذف نمی‌شود. این رفتار با تست واقعی (ردیف یتیم ۴۲۴۲۴۲) اثبات شد.

- DEC-NEW-013 — **قرارداد اجرای مهاجرت** (2026-11-17، Accepted): `MigrationRunner` بازنویسی شد چون نسخه قبلی سه نقص واقعی داشت:
  1. `PRAGMA foreign_keys=OFF` را **داخل** تراکنش صادر می‌کرد؛ SQLite آن را بی‌صدا نادیده می‌گیرد، در نتیجه بازسازی جدول با FK فعال انجام می‌شد.
  2. نام فایل را با `Split('_',2)` می‌خواند و `migration_002.sql` را **بی‌صدا رد** می‌کرد (مهاجرت هرگز اجرا نمی‌شد) — نام‌گذاری استاندارد اکنون `NNN_*.sql` است و فایل بدون پیشوند عددی با لاگ صریح رد می‌شود.
  3. `checksum` هرگز محاسبه نمی‌شد. اکنون SHA-256 متن مهاجرت ذخیره و `DetectDrift()` اختلاف را پیش از اجرا **خطا** می‌کند.
  حالا هر مهاجرت: FK خاموش (و **تأییدشده** با خواندن PRAGMA) → یک تراکنش → `foreign_key_check` و `integrity_check` **قبل از COMMIT** → rollback در هر خطا.
