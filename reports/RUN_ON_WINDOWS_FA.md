# دستورالعمل مو‌به‌مو — از صفر تا اجرای برنامه روی Windows 8.1

آخرین به‌روزرسانی: ۱۴۰۴/۰۸/۲۶ · شاخه: `arena/2e885c97-sorting-os`

---

## ۰. اول از همه: ۴.۷ را پاک کنید، ۴.۸ لازم است

**این را دقیق بخوانید، چون دلیل خطای شما همین است.**

پروژه `.NET Framework **4.8**` می‌خواهد، نه ۴.۷. در هر شش فایل `.csproj`:

```xml
<TargetFramework>net48</TargetFramework>
```

`net48` یعنی ۴.۸. اگر ۴.۷ نصب کنید، Build با خطای
`The target framework 'net48' is not installed` شکست می‌خورد — و اگر ۴.۷ را
«نصب کن» بزنید و بگوید نصب نمی‌شود، احتمالاً یکی از این سه چیز است:

| علامت | علت | راه‌حل |
|---|---|---|
| «نسخه جدیدتری نصب است» | ویندوز شما ۴.۸ دارد، ۴.۷ نمی‌نشیند | **۴.۷ نصب نکنید. بروید مرحله ۱.** |
| خطای `0x800F0922` یا نصب بی‌صدا شکست می‌خورد | بستهٔ ۴.۸ روی ۸.۱ بدون آپدیت‌های پایه | مرحله ۱ پایین |
| «این برنامه روی این سیستم اجرا نمی‌شود» | نسخهٔ ۴.۷ را برای ویندوز ۱۰ گرفته‌اید | بستهٔ مخصوص ۸.۱ |

### تشخیص: الان چه نسخه‌ای دارید؟

`Win + R` را بزنید، تایپ کنید `regedit` و Enter. بروید به:

```
HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full
```

روی `Full` کلیک کنید و مقدار `Release` را بخوانید:

| Release | نسخه |
|---|---|
| ۵۳۳۳۲۰ یا بیشتر | **۴.۸** ✅ کاری ندارید |
| ۴۶۱۸۱۴ | ۴.۷.۲ — کافی نیست |
| ۴۶۰۷۹۸ | ۴.۷ — کافی نیست |

اگر عدد ۵۳۳۳۲۰ یا بالاتر بود، **۴.۷ را رها کنید**؛ مشکل شما جای دیگری است و
مرحله ۲ به بعد جواب می‌دهد.

### نصب ۴.۸ روی Windows 8.1 x64

۱. اول **Windows 8.1 باید آپدیت باشد.** بدون این، نصب ۴.۸ شکست می‌خورد.
   `Control Panel → Windows Update → Check for updates` و همه را نصب کنید.
   اگر Windows Update کار نمی‌کند، بستهٔ
   `Windows8.1-KB2919355-x64.msu` را دستی نصب کنید (پیش‌نیاز اجباری).
۲. بستهٔ آفلاین را بگیرید — **نسخهٔ مخصوص ۸.۱، نه ۱۰**:
   `ndp48-x86-x64-allos-enu.exe`
   از `https://dotnet.microsoft.com/download/dotnet-framework/net48`
   (بخش «Offline installer»).
۳. راست‌کلیک → `Run as administrator`.
۴. **ری‌استارت لازم است.** بعد از ری‌استارت دوباره `Release` را در رجیستری بخوانید
   و مطمئن شوید ≥ ۵۳۳۳۲۰ است.

> اگر روی این ماشین اصلاً به ۴.۸ نرسیدید، بگویید. آن‌وقت دو گزینه داریم:
> یا `LangVersion` و `TargetFramework` را به `net472` پایین بیاوریم، یا
> برنامه را روی ماشین دیگری build کنیم. **الان این تصمیم را نگیرید**؛ اول
> مطمئن شوید ۴.۸ واقعاً نصب نمی‌شود.

به ترتیب:

## ۳. اولین Build — و اینجا **حتماً** چیزی خراب می‌شود

این بخش صادقانه است: **من هرگز این کد را کامپایل نکرده‌ام.** هیچ .NET روی
محیط من نیست. ممکن است ده‌ها خطا بدهد. این طبیعی است و **اتفاق بدی نیست** —
برای همین این مرحله وجود دارد.

در `Developer Command Prompt for VS 2019`:

```
cd C:\SORTING-OS
msbuild src\Mazandasht.sln /p:Configuration=Debug /p:Platform=x64 /v:minimal
```

### چه اتفاقی می‌افتد

| اگر دیدید | معنی | کار |
|---|---|---|
| `Build succeeded` | باورنکردنی است ولی ممکن است | بروید مرحله ۴ |
| `error CS0246: namespace ... could not be found` | `using` جاافتاده | **متن کامل خطا را برایم بفرستید** |
| `error MC3074` / `MC3000` | خطای XAML | همان |
| `error NU1101: Unable to find package` | NuGet آفلاین است | مرحله ۳.۱ |
| `The target framework 'net48' is not installed` | ۴.۸ نصب نیست | مرحله ۰ |

### ۳.۱ اگر NuGet بسته‌ها را پیدا نکرد

شبکهٔ شما ممکن است به nuget.org دسترسی نداشته باشد. دو بسته لازم است:

| بسته | نسخه | کجا لازم است |
|---|---|---|
| `System.Data.SQLite` | `1.0.118` | `Mazandasht.Persistence` |
| `xunit`, `xunit.runner.visualstudio`, `Microsoft.NET.Test.Sdk` | 2.6.1 / 2.5.3 / 17.8.0 | فقط تست‌ها |

**برای برنامه اصلی، فقط `System.Data.SQLite` حیاتی است.** اگر تست‌ها را هم
می‌خواهید، همه.

راه آفلاین:
۱. روی ماشینی با اینترنت، `https://www.nuget.org/packages/System.Data.SQLite/1.0.118`
   را باز کنید و `.nupkg` را دانلود کنید.
۲. در `C:\SORTING-OS` پوشهٔ `packages-local` بسازید و فایل را آنجا بگذارید.
۳. فایل `src\NuGet.config` بسازید با این محتوا:

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="local" value="..\packages-local" />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
  </packageSources>
</configuration>
```

> **هشدار که نمی‌توانم تأییدش کنم:** نسخهٔ `1.0.118` را من از روی اینترنت
> چک نکردم (nuget.org از محیط من بسته است). اگر `NU1102` گرفتید، یعنی آن نسخه
> موجود نیست — عدد را عوض کنید. اگر `NU1101` گرفتید، نام بسته غلط است.
> **متن دقیق خطا را بفرستید.**

## ۵. ساخت پایگاه داده و اجرا

برنامه خودش پایگاه داده را می‌سازد (`MigrationRunner`)، ولی مسیرش را باید
بدانید یا تعیین کنید.

### گزینهٔ الف — اجرا از داخل VS

۱. `src\Mazandasht.sln` را باز کنید.
۲. در Solution Explorer روی `Mazandasht.Presentation` راست‌کلیک → `Set as Startup Project`.
۳. بالای پنجره، `Debug` و `x64` را انتخاب کنید (نه `Any CPU`).
۴. `F5`.

### گزینهٔ ب — اجرا از خط فرمان

```
cd C:\SORTING-OS
set MAZANDASHT_DB=C:\SORTING-OS\data\mazandasht.db
mkdir data
src\Mazandasht.Presentation\bin\x64\Debug\net48\Mazandasht.exe
```

مسیر خروجی ممکن است کمی متفاوت باشد؛ اگر پیدا نکردید:

```
dir /s /b src\*Mazandasht.exe
```

### کجا پایگاه داده ساخته می‌شود

به ترتیب:

۱. اگر متغیر محیطی `MAZANDASHT_DB` ست شده باشد → همان مسیر.
۲. وگرنه `%ProgramData%\Mazandasht\mazandasht.db`.

اگر برنامه گفت «پایگاه داده پیدا نشد»، یعنی هر دو مسیر قابل نوشتن نبودند —
همان پیام را روی صفحه می‌بینید، برنامه کرش نمی‌کند.

## پیوست — اگر همه‌چیز شکست خورد

اگر روی ۸.۱ به هیچ نتیجه‌ای نرسیدید، بگویید. سه مسیر جایگزین دارم:

۱. **پایین آوردن هدف** به `net472` (داخل ۸.۱ بدون آپدیت هم معمولاً هست).
   کار کمی است ولی باید تست‌ها را دوباره بررسی کنم.
۲. **ماشین دیگر:** اگر یک ویندوز ۱۰ بدون VS دارید، از
   `Build Tools 2022` می‌شود build گرفت و خروجی را روی ۸.۱ اجرا کرد
   (`net48` روی ۸.۱ با ۴.۸ نصب‌شده اجرا می‌شود).
۳. **GitHub Actions:** می‌توانم یک workflow بنویسم که روی سرور گیت‌هاب
   build کند و فایل `Mazandasht.exe` را به شما بدهد. برای این باید کد را
   push کنید و runner های گیت‌هاب روی `windows-latest` کار می‌کنند که ۴.۸
   دارد. این سریع‌ترین راه برای «فهمیدن اینکه کد کامپایل می‌شود یا نه» است —
   حتی اگر خودتان VS نصب نکنید.

مورد ۳ را می‌توانم همین الان آماده کنم. بگویید شروع کنم.
