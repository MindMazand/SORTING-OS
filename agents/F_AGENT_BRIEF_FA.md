# ایجنت F — مرکز واردسازی (رابط کاربری)

**دستور:** موتور واردسازی اثبات‌شده را از پشت خط فرمان به دست مالک برسان.
هیچ منطق واردسازی جدیدی ننویس — فقط `ImportRunner` را صدا بزن.

## مسئله واقعی

موتور ۳۹/۳۹ تست دارد، ۱۱ قالب واقعی را می‌خواند، ۶٬۴۴۹ ردیف در ثانیه، و
برگشت دقیق. ولی **بدون رابط، مالک نمی‌تواند از آن استفاده کند**. یک موتور
بی‌رابط همان چیزی است که «ساخته شد» ولی «کار نمی‌کند».

## چهار تصمیم که این UI باید بگیرد

1. **پیش‌نمایش پیش‌فرض است، ثبت استثنا.** دکمه اصلی «بررسی فایل» است. ثبت
   دکمه دوم است و قبلش تعداد ردیف و تعداد خطا را می‌گوید. `upload ≠ commit`
   قاعده مالک است، نه یک گزینه.

2. **خطاها به زبان مالک.** `ImportRunner` پیام‌های فارسی می‌دهد؛ UI همان را
   نشان می‌دهد و از خودش چیزی نمی‌سازد. نگاشت خطا به «خطای نامشخص» یعنی مالک
   نمی‌فهمد کدام سلول مشکل دارد.

3. **تاریخچه دسته‌ها واقعی است.** `ListBatches` تازه اضافه شد. هر سطر:
   کد، فایل، قالب، وضعیت، تعداد، و دکمه برگشت فقط وقتی مجاز است.

4. **برگشت با تأیید صریح.** دکمه برگشت یک دیالوگ می‌خواهد که می‌گوید چند سند
   حذف می‌شود و اینکه حذف برگشت‌ناپذیر است. حذف داده مالی بدون تأیید، حتی با
   کلیک اشتباه، فاجعه است.

## چیزی که ساخته نمی‌شود

انتخابگر ستون دستی. قرارداد قالب‌ها ستون‌ها را با نام فارسی و انگلیسی نگاشت
می‌کند و دروازه parity آن را تضمین می‌کند. UI ای که به مالک اجازه دست‌کاری
نگاشت بدهد، دقیقاً همان دری است که داده را به ستون اشتباه می‌برد.
